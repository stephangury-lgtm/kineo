# Supports de cours dans Leryko — 14 octobre 2026

Les 24 documents locaux déjà référencés dans `course_documents` disposent maintenant de copies dans le bucket privé `documents`, sous `courses/local-courses-2026-10/`. Leurs identifiants et les références des questions/leçons sont conservés. Huit CM d’anatomie absents des dossiers du PC ont été récupérés depuis leurs fichiers Google Drive existants ; les seize autres supports viennent des PDF locaux dans le dossier IFMK. Les archives IFSI ont été inventoriées, mais n’ont pas été importées en masse : les fiches IFSI utilisent déjà le contenu en base et n’ont aucun lien Drive.

Les 24 PDF représentent exactement 74 831 569 octets. Les en-têtes PDF, les empreintes SHA-256 des copies locales, les tailles hébergées et les checksums multipart du stockage ont été vérifiés. Les empreintes SHA-256 attendues sont conservées dans `course_documents.file_sha256`. Le manifeste détaillé et les copies locales restent en dehors du dépôt applicatif ; aucune URL de téléchargement signée ni clé serveur n’est publiée.

`/document/:documentId` ouvre le PDF dans Leryko. Un utilisateur connecté disposant d’un profil obtient les métadonnées d’un document validé réellement hébergé, puis une URL signée de quinze minutes via les règles Storage existantes. Le bucket reste privé. Le bouton « Actualiser l’accès » renouvelle le lien. Les deux nouvelles RPC utilisent les droits de l’appelant et les règles RLS, sans privilèges élevés. Les sources d’une leçon exposent l’identifiant du support et sa disponibilité, avec un bouton « Lire le cours ». La bibliothèque présente tous les PDF disponibles dans « Cours originaux ».

Les quatre anciennes références cliquables au CM3 dans `lessons.sources` doivent être remplacées par une route interne seulement après vérification du déploiement du lecteur. Les fichiers d’origine et leurs paramètres de partage Google Drive ne sont pas supprimés ni modifiés. Les références officielles externes (HAS, UNESS, etc.) sont conservées.

Les migrations `20261014204519_private_course_documents.sql` et `20261014205040_course_document_invoker_rls.sql` sont appliquées en production. La bascule des 24 chemins et des tailles a été exécutée dans une transaction avec contrôle du manifeste, de chaque chemin existant et de chaque objet hébergé. Une migration ne contient pas d’identifiants de documents générés. La suite SQL teste les deux RPC sous le rôle étudiant, le refus des comptes sans profil et des documents absents, et l’absence d’accès anonyme ; toutes ses identités sont générées puis annulées avec ROLLBACK.

Six tests de navigateur (Chromium, Firefox et WebKit) vérifient l’ouverture avec une URL temporaire, le renouvellement et le refus d’accès sans repli vers Drive. Compilation, invariants de source et budgets de build vérifiés.
